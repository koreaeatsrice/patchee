# Settings — `config/patchee.cfg`

Patchee has **one** settings file. Everything can be turned on or off there.

It appears after the first start, at:

```
<server folder>/config/patchee.cfg
```

## How to change a setting

1. **Stop the server first.**
2. Open the file in Notepad (Windows) or any text editor.
3. Change the value — usually `true` to `false` (or the other way around); some settings are numbers or lists. **Only change the values, never the names.**
4. Save the file.
5. **Start the server again.** (Changes are read at startup.)

Everything after a `#` on a line is a note for humans — the game ignores it.

## The switches

| Setting (name in the file) | What it does | Default | Change it when… |
|---|---|---|---|
| `enabled` | **Master switch for the whole mod.** `false` = Patchee does nothing at all. | `true` (on) | You want to turn everything off at once while keeping the file. |
| `enableDollyFix` | Lets the JABBA Dolly pick up bee houses (Forestry apiary + bee house, Gendustry industrial apiary, MagicBees magic apiary), bees inside. | `true` (on) | You do not want players to move bee houses. |
| `enableMattockFix` | The Tinkers' Construct mattock digs sand and snow like a shovel. | `true` (on) | You want the old slow digging back. |
| `enableSuperTankFix` | No hunger / slow legs / slow mining / weakness from carrying a **filled** GregTech Super Tank or Super Chest, on a player whose client also runs Patchee. A stock client keeps GregTech's normal debuff and its timer. The two sides must agree: the server clears for any player whose client reports Patchee, whatever that client's own setting is, so turning the client setting off alone leaves you seeing a debuff the server has already cleared. | `true` (on) | You want the vanilla GregTech behaviour back — true only when the client setting is off too. |
| `enableGlassBreakFix` | No **bleeding** and no **blindness** from breaking glass. Chisel's **Transparent Technical Block** (the metal-mesh `technical2` one) is not glass at all, so it never cuts you. **Real** glass (vanilla, Chisel glass, stained glass, EFR tinted glass) still cuts a player wearing **no armour** — that is the pack's flavour — but armour protects; see `glassBreak.minArmourPieces`. Server-side only: clients need nothing. | `true` (on) | You want Blood Arsenal's cut on every glass block, armour or not. |
| `enableVeinConfig` | Keeps **VeinMiner** under server control: rewrites its settings at every server start so only sand (both kinds), clay and gravel can be vein-mined, 64 blocks max. | `true` (on) | You want VeinMiner's own settings left alone. |
| `enableLightOverlayTweak` | **Client-side.** On a client that has Patchee installed, NEI's F7 light overlay marks only pitch-dark blocks instead of NEI's fixed levels. | `true` (on) | You want NEI's F7 overlay exactly as it ships. |
| `enableAuroraBreak` | The aurora blocks (block, pillar, slab and double slab) break in at most 10 ticks (a floor of 0.1 per tick, the same rate as the Final Castle) for a player who has killed the Snow Queen (earned the Glacier progression). They are also marked pickaxe-harvestable, so the Tinkers' Construct hammer's 3x3 area-mine works on them. The gate is read **per player on every break**, so a player without it breaks them at the plain 1.7.10 speed. The faster break is only **seen** on a client that has Patchee installed; the server half is what keeps the two in step (it stops the server refusing the faster break). A floor, never a slowdown. The same rate applies when an aurora block is built into Forge Multipart microblocks, ArchitectureCraft shapes, Carpenter's Blocks covers or LittleTiles tiles. | `true` (on) | You want the plain 1.7.10 speed back. |
| `enableArcticFurBreak` | The arctic fur block gets the modern speed while shears are held: it breaks in at most 5 ticks. The faster break is only **seen** on a client that has Patchee installed; the server half is what keeps the two in step (it stops the server refusing the faster break). A floor, never a slowdown: without shears it breaks exactly as it does today. | `true` (on) | You want the plain 1.7.10 speed back. |
| `enableTeamChunkCap` | **ServerUtilities only.** A **team** gets its **best member's own per-rank limit** as its chunk limit. ServerUtilities normally adds the members' limits up, so a 4-player team would end up with 6000 / 2000. With this on, a team of ordinary players gets one player's total (the player rank's 1500 / 500) no matter how many members it has, and a member whose rank carries higher numbers — an admin — keeps them; nothing is ever capped below what a member's own rank grants. A player on their own is **not** affected (their sum already is their own number). Server-side only: clients need nothing. | `true` (on) | You want ServerUtilities' own per-member totals back. |
| `enablePollutionNoVisuals` | **Client-side, on by default.** On a client that runs Patchee, GregTech's smog, fog colour shift, smoke particles and grass/leaf/water/flower tints are not drawn. Patchee turns GregTech's own **Pollution Fog** and **Pollution Dirt** render flags off in memory every tick and, when `config/GregTech/Client.cfg` exists, writes both of them to `false` in that file (timestamped `.bak`, only those two lines); it also keeps GregTech's five block-tint tables empty, so tints are not drawn. The server always sends every client the real pollution number — no packet is changed, `Pollution.cfg` is not edited and the server is not affected. Pollution itself keeps running in full on the server. | `true` (on) | You want GregTech's pollution visuals back on that client. |
| `enableFinalCastleBreak` | For a player who has killed the Snow Queen (earned the Glacier progression): the castle bricks (`castleBlock`), the castle magic blocks (`castleMagic`), the two castle doors (`castleDoor`, `castleDoorVanished`), the castle unlock block (`castleUnlock`), the thorn wall (`thorns`), burnt thorns (`burntThorns`), the thorn rose (`thornRose`) and Weathered Deadrock (`deadrock`, metas 0-2) break in at most 10 ticks (a floor of 0.1 per tick), never a slowdown; the gate is read **per player on every break**, so a player without it breaks them at the plain 1.7.10 speed; the faster break is only **seen** on a client that has Patchee. **On the server**, the same progression also makes the castle bricks stop draining the pickaxe 16x and the thorn wall stay broken instead of growing back and multiplying. Players without the progression keep the stock behaviour. The same rate applies when a castle block is built into Forge Multipart microblocks, ArchitectureCraft shapes, Carpenter's Blocks covers or LittleTiles tiles. | `true` (on) | You want Twilight Forest's stock castle bricks and thorn wall back. |
| `enableEnrichedFertilizerRecipe` | Keeps the old **enriched fertilizer** recipe as an extra choice next to the pack's newer one: **4 fertilizer + 1000 L fertilizer liquid → 1000 L enriched fertilizer** in a **Chemical Reactor** or **Large Chemical Reactor** (LV, 1 second). Only adds a recipe; the pack's own recipe is untouched. Needs CropsNH and GregTech (both ship with GT:NH). The recipe works in the machine on both sides; on a **client that has Patchee** the NEI recipe cache is dropped so the recipe also **shows up in NEI** (a client without Patchee does not see it). | `true` (on) | You want only the pack's own recipe. |
| `enablePollutionNoNegatives` | **GregTech** pollution stays on, but has no downsides and no smog. Patchee rewrites `config/GregTech/Pollution.cfg`: `Activate Pollution=true` and the four effect limits (poison, smog, sour rain, vegetation) at 2147483647. GregTech reads that file in its own coremod first, so the file change lands on the next boot; the same five values are forced in memory after GregTech loads, which is what fixes the current boot, so a read-only file or a hand edit cannot bring the effects back. Only those five lines change, and the original is kept as a timestamped `.bak`. On a client it also turns off the **Pollution Fog** and **Pollution Dirt** render flags in memory, and in `config/GregTech/Client.cfg` when that file already exists (GregTech writes it on its first launch). It does **not** empty the block-tint tables, so grass, leaf, water and flower tints still need `enablePollutionNoVisuals`. | `true` (on) | You want GregTech's own pollution effects back. |
| `enableFishTrapMoves` | Makes Pam's HarvestCraft **Fish Trap** work with **InventoryBogoSorter**: space+click moves all, alt+click moves the same item, ctrl+click moves one, middle-click sorts the 18 output slots. Bait from your inventory goes into the trap's bait slot. The move hotkeys (space/alt/ctrl-click) work from the server jar alone; sorting the trap's output with middle-click (and the sorter's sort button in that GUI) needs Patchee on the client too. Plain shift-click already works. | `true` (on) | You want the stock Fish Trap GUI back. |
| `enableChestplateHoverLift` | The IC2 Quantum Chestplate's hover mode rises and sinks at the same speed, and that speed is the one it already flies sideways at — at full charge and normal altitude: while hovering, holding jump rises and holding sneak sinks at **0.089 blocks a tick**. That is not a new number — it is IC2's own hover horizontal speed (its `0.4` forward push times its `0.02` friction, divided by `1 - 0.91` air drag), so up, down and sideways all match. Below 5% charge or near the build limit IC2 scales its own sideways speed down while this vertical target stays fixed, so the match is only exact at full charge and normal altitude. With no key held stock IC2 still sinks at `0.025`, or at `0.0` when Hodgepodge's own hover fix is on (its default). IC2's own hover was `0.1` up and `-0.1` down with sneak. This does make the climb **slower** than the old `0.6` ceiling, on purpose, so it matches sideways. The patch rewrites IC2's jump clamp and **adds** the sink as an extra store after IC2's own `-0.1` one, which is left in the class so Hodgepodge's hover tweak keeps working and nothing that matches stock literals by value loses its target; `-0.025` itself is never touched. IC2 sends your key state to the server in its own packet, so both sides take the new speeds (the server's copy arrives one tick later); install the same jar on both so they agree. | `true` (on) | You want IC2's own hover speed back. |
| `enableChestplateGroundGuard` | Standing on the ground with the IC2 Quantum Chestplate's jetpack and hover mode on is **not** treated as flying. IC2 runs the jetpack tick while you hold jump (or while you are still falling), and while you are on the ground and not rising that tick is now skipped, so the game stops clearing your fall distance and its server-side anti-fly counter. The jetpack loop sound stops on those ticks, because the skipped tick's return value is what keeps it playing. You still lift off when you jump: the guard stops applying the moment you leave the ground. | `true` (on) | You want IC2's own on-the-ground behaviour back. |
| `enableChestplateHoldAltitude` | In the IC2 Quantum Chestplate's hover mode, holding **sneak and jump together** holds your height instead of moving: the vertical target is set to 0; a climb already in progress settles to level over a few ticks. Each key on its own keeps its new symmetric speed (shift alone sinks at 0.089 a tick, jump alone rises at 0.089 a tick). Applied on both sides, same as the climb above. | `true` (on) | You want IC2's own shift+space behaviour back (it drifts up). |
| `glassBreak.minArmourPieces` (advanced) | How many of the four **armour slots** must hold something for a player to count as protected from glass cuts. Any item in the slot counts. `0` = armour never protects, `4` = a full set, `1` = any single piece. Values outside 0-4 are clamped. | `1` | You want a stricter or looser rule. |
| `lightOverlay.maxLightNormal` | **Client-side.** The light level the F7 overlay marks at, in every dimension (the Nether included). `0` = only pitch-dark blocks. | `0` | You want it stricter or looser. |
| `veinConfig.blockLimit` | The most blocks **one vein** may have. | `64` | You want shorter or longer veins. |
| `veinConfig.radius` | How far from the first block VeinMiner looks for more of the same block. | `20` | You want a tighter or wider search. |
| `veinConfig.blocks` | The blocks that may be vein-mined, separated by commas. Format: `mod:block` or `mod:block/data` (data = exact variant; no data = all variants). | `minecraft:sand/0,minecraft:sand/1,minecraft:clay,minecraft:gravel` | You want to allow or remove blocks. |
| `veinConfig.extraTools` (advanced) | Extra item names treated as shovels for vein mining, separated by commas. | empty | Another mod adds a shovel-like tool you want to work. |
| `extraDollyClasses` (advanced) | Extra block types the Dolly should accept. One internal class name per line. | empty | Another mod adds a block you want to move **and** a dev told you the exact class name. Not sure? Leave it empty. |
| `runSelfTest` (advanced) | Runs a quick check at server start and writes PASS/FAIL per check to the log. Changes nothing in the game. | `false` (off) | You just installed or updated and want to be sure. Turn on, restart, read the log, turn off again. |

## Honest side notes

- **Dolly fix:** a moved apiary keeps the direction it was facing (cosmetic only). Natural world hives and the big multi-block Alveary are deliberately **not** included. Moving a block out of a finished Alveary still breaks it — same as mining it.
- **Mattock fix:** other mods still see the mattock as an axe only — same as the game always did. Nothing else about the tool changes.
- **Supertank fix:** the four effects are cleared only for players whose client also runs Patchee. A stock client is untouched and keeps GregTech's normal debuff and its timer. While a filled tank/chest is carried, those four effects are cleared whatever their source (the pack's pollution can also use them). No packet channel is added and clients stay optional: [CLIENT-MODS.md](CLIENT-MODS.md).
- **Glass cuts (Blood Arsenal):** the two effects are taken away inside the **same block-break event**, so no damage and no blindness ever get a tick. The blindness is removed by potion id, so it takes away **any** blindness the player already had, from any source — not just Blood Arsenal's. An existing bleed from a fight is cleared as well, whatever gave it to you. **Silk touch** still protects you — that is Blood Arsenal's own check, not Patchee's. If Blood Arsenal is not installed, the fix does nothing and the log says so. Server-side only: no client copy is needed, and `runSelfTest=true` prints a `[SelfTest] PASS` line for it.
- **VeinMiner fix:** it needs **VeinMiner installed on the server** — the pack does not include it ([INSTALL-SERVER.md](INSTALL-SERVER.md) has the optional part). **Never edit the files in `config/veinminer/` yourself** — Patchee rewrites them at every start. Players without the VeinMiner client mod can still vein-mine: type `/veinminer mode sneak` once (again after a server restart), then sneak while mining.
- **F7 overlay tweak:** this one is **client-side only**. It changes what the F7 overlay marks on a client that has Patchee installed; a player without Patchee sees NEI's normal overlay. The server does not need NEI. The number is the light level the X appears **at** — so `0` means only pitch-dark blocks, in every dimension. It is applied while NEI loads, so change the value and restart the game for it to take effect.
- **Twilight Forest break speeds:** the faster break is only **seen** on a client that has Patchee installed. Unlike the F7 overlay, this rule runs on **both sides** — the server half is what stops the server refusing the faster break. The rules are a floor — nothing ever breaks slower than it did before, they only add the modern speed. The condition is checked **per player on every break**: the aurora blocks (10 ticks), the castle blocks (10 ticks) and Weathered Deadrock (10 ticks) need the Glacier progression (the Snow Queen), so a player who has not killed her breaks them at the plain 1.7.10 speed; the arctic fur block (5 ticks with shears) needs nothing but shears in hand. The aurora blocks are also marked pickaxe-harvestable so the Tinkers' Construct hammer's 3x3 area-mine works on them. Patchee changes the game at runtime through reflection; it copies no Twilight Forest code and ships none of its art or sounds. If Twilight Forest is missing, the rules do nothing. This holds for blocks built into other mods' shapes too — microblocks, shapes, covers and tiles all break at the same rate. Only ArchitectureCraft shapes work with the Tinkers' hammer 3x3; the other wrappers keep their own tool on purpose, so the hammer does not area-mine every material they can hold. The boot log has one `wrapper coverage` line for each of these mods that is installed.
- **Team chunk limits (ServerUtilities):** ServerUtilities adds every member's own limit together for the whole team, so a team of four would be allowed 6000 claimed chunks and 2000 loaded ones. Patchee reads a team's limit from its **members' per-rank settings** instead: the best member's own limit becomes the team max, so a team of ordinary players gets one player's total (1500 claimed / 500 loaded on this pack) however many members it has — and a member whose rank carries higher numbers, such as an admin, keeps them; nothing is ever capped below what a member's own rank grants. A player on their own is left exactly as they were. The old `teamChunkCap.maxClaimChunks` / `teamChunkCap.maxLoadedChunks` number keys from earlier versions are retired — leave them in the file or delete them, they change nothing. This is a **server-side** rule; the numbers the claim map shows are computed on the server and sent to the client, so every player sees the real numbers without installing anything. It is read while the server starts, so restart after changing it. If ServerUtilities is not installed, the rule does nothing and the log says so.
- **Pollution visuals (GregTech):** **on by default, and it is a client-side switch.** The server always sends every client GregTech's real pollution number; Patchee never changes that packet, in any configuration. On a client that runs Patchee, `enablePollutionNoVisuals` takes away what players **see**: the smog, the fog, the fog colour shift, the smoke particles and the grass/leaf/water/flower tints.
- **What the client switch changes:** it turns GregTech's own `Pollution Fog` and `Pollution Dirt` render flags off in memory every tick, and when `config/GregTech/Client.cfg` already exists it writes both of them to `false` in that file, keeping whichever spelling the line already has — `B:"Pollution Fog"` / `B:"Pollution Dirt"` on newer builds, or the older `B:renderPollutionFog` / `B:renderDirtParticles` — and never renames a key. Only those two lines change, and the original is kept next to it as a timestamped `.bak`. It also keeps GregTech's five block-tint tables (standard blocks, liquids, double plants, crossed squares, vines) empty, so tinted grass, leaves, water and flowers are not drawn. GregTech can rebuild its tint tables when a world loads, so the guard checks them on every client tick and empties them again.
- **If your config already says `false`:** an existing config file that already carries `enablePollutionNoVisuals=false` keeps it off — delete that line to take the new default of `true`.
- **What it does not do:** it does not change the pollution packet, does not edit `config/GregTech/Pollution.cfg`, does not lower or remove pollution, and has no effect on a dedicated server. Pollution itself keeps running in full: production, accumulation, decay, chunk storage, damage, sour rain, vegetation checks, scanners, the pollution detector and every machine reading pollution keep their exact server-side numbers.
- **The honest caveat:** a player who does **not** run Patchee still sees GregTech's smog, fog and particles when pollution is high enough, because the server really does send that player the real number. These flags only help players who install Patchee. With `enablePollutionNoVisuals=false`, the plant and water tints return on **that client**, but fog and particles stay off while the separate default-on `enablePollutionNoNegatives` is on; the server and other players are unchanged. If GregTech is not installed, the fix does nothing and the log says so.
- **Fish Trap (HarvestCraft + InventoryBogoSorter):** only the 18 fish output slots are one sort group, so middle-click sort can never pull the bait out of its slot and stop the trap. Space+click and alt+click on the **bait slot** therefore do not move bait out; ctrl+click and plain shift-click still do. Moving items **into** the trap always routes bait to the bait slot and refuses anything else. The move hotkeys (space/alt/ctrl-click) work from the server jar alone; sorting the trap's output with middle-click (and the sorter's sort button in that GUI) needs Patchee on the client too. Plain shift-click already works. If either mod is missing, the fix does nothing and the log says so.
- **Chestplate flight (IC2):** the climb, the sink and the shift + space hold are applied on **both sides**. The climb and the sink are one edit: jump rises at 0.089 a tick and sneak sinks at the same 0.089, IC2's own hover horizontal speed, so up and down match the way you already fly sideways. If IC2's class has no hover+sneak clamp in it, both are left at stock rather than raising the climb on its own - that would put the old up/down mismatch back, and the log says so. IC2 forwards your key state to the server in its own packet (`IC2.network.initiateKeyUpdate` to `Keyboard.processKeyUpdate`), and sneak is read from the player itself, so the server takes the same branches as the client - one tick behind, and only after the first key change, because IC2 sends a packet only when the key state changes. Put the same jar on both sides so the two agree; a client without Patchee keeps IC2's own hover behaviour and drifts out of step with a patched server in both directions, not only the climb: the server sinks at 0.089 a tick where an unpatched client still sinks at 0.1. The ground guard runs on both sides as well, because the anti-fly counter only exists on the server. IC2 ships closed source, so Patchee copies none of its code: it checks the method's shape while the class loads and refuses anything it does not recognise, leaving the class exactly as it ships.
- **Jetpack flight (GraviSuite):** the same three switches cover GraviSuite's Advanced Jetpack, and the Advanced Nano Chestplate uses the jetpack's own code. In hover mode the jetpack now rises AND sinks at 0.1156 a tick - its own hover sideways speed, at full charge and normal altitude - where stock GraviSuite climbed at 0.2 and sank at -0.2 (0.2 up / -0.2 down) and the previous Patchee release climbed at 0.6. So this release's rise and sink are slower than the last release's climb, on purpose: up matches down and both match sideways. Hover with no key held still sinks at GraviSuite's own hover fall speed, and the boost key still doubles whichever speed you picked, exactly as GraviSuite ships it. Sneak + jump holds height instead of sinking, and standing on the ground is not counted as flying. GraviChestPlate is a different item with its own path (it turns on the player's creative-flight flags), so it is left exactly as it is: it never clears the anti-fly counter, and it does not pair jump with sneak - its boost mode adds and subtracts them separately. GraviSuite also forwards key state to the server, so both sides apply the rise, the sink and the hold; a server-only install is out of step in BOTH directions, not only the climb - the server sinks at -0.1156 while an unpatched client still sinks at -0.2. **On GraviSuite Neo:** Patchee leaves the stock -0.2 literal in the class, so Neo's own constant matcher still finds its target, and adds the new sink as an extra store just after it. If Neo has already transformed that store into an expression (its own 'jump value minus 0.2' shape), Patchee cannot see the site at all and skips the rise, the sink and the shift + space edit together - the result is PARTIAL and the log says so - leaving Neo's own behaviour in place, while the ground guard still applies. GraviSuite is closed source, so Patchee copies none of its code: it checks the method's shape while the class loads and hands the class back unchanged if it does not recognise it.
- **Pollution (GregTech):** pollution stays on. Patchee rewrites `config/GregTech/Pollution.cfg`: `Activate Pollution=true` and the four effect limits at 2147483647, so pollution still builds up and decays but no effect threshold is ever reached. Only those five lines change, and the original is kept next to it as `Pollution.cfg.<time>.bak`. GregTech reads that file in its own coremod first, so the file change lands on the next boot; the same five values are forced in memory after GregTech loads, which is what fixes the current boot, so a read-only file or a hand edit cannot bring the effects back. On a client it also turns the Pollution Fog and Pollution Dirt flags off in memory and, when `config/GregTech/Client.cfg` already exists, in that file. That client half only helps players who install Patchee themselves: a player without it still sees the smog the server reports.
- All fixes fail soft: if one of the patched mods is missing or changed shape, that fix simply does nothing and writes a note in the log. The server always starts.

## Want the check output explained?

Set `runSelfTest=true` and look for lines like `[SelfTest] PASS …` and finally `[SelfTest] result: N passed, 0 failed`. That is Patchee proving to you that its changes work on **your** server. Then set it back to `false`.
